# maps/ - one folder per map

Each folder under `maps/` is one map of the world (or a country) divided into equal-population parliament seats.
`maps/world-500/` is the map in use today (500 seats of about 16.6 million people). Later maps follow the same shape:
`world-250`, `india-543`, ...

The game (`../game/`) uses `maps/` as a library: **any `maps/<id>/` that has a valid `map.json` works with no code changes.**

## What a map folder contains

```
maps/<id>/
  map.json            manifest (below) - this is what makes the folder a map
  thumbnail.jpg       ~640 px wide picture of the map (shown in the game's map chooser)
  site/               the static study website - everything needed to RENDER the map, nothing else
    index.html  app.js  style.css  lib/
    data/
      world.topo.json   coarse TopoJSON, one feature per seat (id = seat number)
      detail.topo.json  detailed TopoJSON, loaded lazily when zoomed in
      seats.json        seat names (authoritative), population, countries / ADM1 / ADM2 covered
      candidates.csv    optional: 10 fictional local-sounding candidate names per seat (header candidate_1..10, row n = seat n)
      game.json         game package: centroids, neighbour graph, phase groupings k = 1..5 (see below)
  source/             the editing toolkit - files needed to CHANGE the map, never needed to render it
    README.md           how to edit seats / geometry and rebuild
    build/  data/  output/  GEO/  reference/
```

Everything the browser needs is under `site/` (it is deployed as-is to GitHub Pages for `world-500`, and copied into
the game's web build under `/maps/<id>/`). `source/` is never deployed.

### map.json (manifest)

Matches `MapManifest` in `game/shared/src/types.ts`. Paths are relative to `maps/<id>/`.

```json
{
  "id": "world-500",
  "name": "World – 500 seats",
  "description": "…",
  "seatCount": 500,
  "thumbnail": "thumbnail.jpg",
  "site": "site/index.html",
  "gamePackage": "site/data/game.json"
}
```

`id` must equal the folder name.

### game.json (game package)

`GameMapPackage` in `game/shared/src/types.ts`: `mapId` (= folder name), `seatCount`, `seats[]` (`id`, `name`, centroid
`lon/lat` and projected `x/y`, `neighbours`), `phaseGroups` (keys `"1"`..`"5"`: seat ids polled in each phase, a
contiguous exact partition of all seats) and `topo` (`coarse` / `detail` topo file names, relative to game.json's folder).
For `world-500` it is generated by `source/build/07_game_map.py`.

## How the game discovers maps

`game/scripts/gen-maps.ts` (`npm run gen:maps` in `game/`; also run before `npm test`) scans `maps/*/map.json`,
validates each manifest and its game package (file existence, `seatCount` matches, `phaseGroups` 1..5 each partition
the seats exactly once, neighbours exist) and writes two committed files:

- `game/shared/src/maps.generated.ts` - `MAP_MANIFESTS` (used by the web app and the server),
- `game/server/src/maps.generated.ts` - `GAME_PACKAGES`, static imports of every `game.json` (bundled into the Lambdas).

The web build (`game/web/vite.config.ts`) serves `maps/**` at `/maps/**` in dev and copies each
`maps/<id>/{map.json, thumbnail.*, site/**}` to `dist/maps/<id>/`, so files are at `/maps/<id>/site/data/seats.json` etc.
Per-map game tuning lives in `game/shared/src/mapConfig.ts` (`MAP_CONFIGS`); a map without an entry gets a copy of the
world config until tuned with the simulator (`game/sim`).

## Adding a new map

1. Create `maps/<id>/` with `site/` (copy `world-500/site` and change data/titles) and `source/` (the toolkit for that map).
2. Produce `site/data/{world.topo.json, detail.topo.json, seats.json, game.json}`; for the game package adapt
   `source/build/07_game_map.py` (it takes the map id from the folder name).
3. Write `map.json` and generate `thumbnail.jpg` (headless-Chrome screenshot of `site/`, about 640 px wide).
4. `cd game && npm run gen:maps` - fix any validation errors it prints; commit the regenerated files.
5. (Optional) add a tuned `MapConfig` to `MAP_CONFIGS` after running the simulator.
